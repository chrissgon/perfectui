# perfectui

Perfect UI is "An exceptionally lightweight and highly customizable CSS and JavaScript library for crafting elegant user interfaces" (`README.md`). It ships the bare minimum: no runtime dependencies, no CSS reset, no font import, and no rule that is not attached to a `pui-` class; behaviour comes from the browser and JavaScript only fills in what a browser is missing. Published on npm as `@chrissgon/perfectui`, MIT. The library is migrating from `0.23.0` (SCSS) to `1.0.0` (native CSS and native HTML APIs); the package is at `1.0.0-beta.0`.

## Architecture

`ARCHITECTURE.md` is the source of truth: §2 hard rules (never broken), §4.1 approved size multipliers, §11 build and package, §12 testing, §14 open questions, §15 migration phases checklist. `HANDOFF.md` is status and history. `design-system/DESIGN-SYSTEM.md` documents tokens and components and is regenerated by a script. `MIGRATION.md` is the 0.23 → 1.0 guide for users.

## Commands

## Conventions

- Conventional Commits, enforced by commitlint (`@commitlint/config-conventional`) through the husky `commit-msg` hook. Breaking changes use `!` in the header and a `BREAKING CHANGE:` footer.
- The husky `pre-commit` hook runs lint-staged: it formats and lints only the staged files and stages the result back. Do not run `bun run format` beforehand to compensate; that produced a long tail of `style:` commits before lint-staged existed.
- Prettier: 2-space indentation, semicolons, no trailing commas, LF line endings (`.prettierrc`). ESLint: `@eslint/js` recommended plus typescript-eslint recommended on `**/*.ts`; `dist/`, `node_modules/` and `*.d.ts` are ignored (`eslint.config.mjs`).
- Code, comments, commits and documentation in English.
- Migration work happens on branch `v1`.
- Do not change the approved size multipliers (`ARCHITECTURE.md` §4.1) without asking.
- Every pull request reports the gzip size of `dist/` (`ARCHITECTURE.md` §2, rule 12).

## Testing

Playwright specs live in `tests/` (`tests/composition.spec.ts`, `tests/fallbacks.spec.ts`, `tests/mode.spec.ts`), with fixtures in `tests/fixtures/` and manual pages in `tests/manual/`. CI installs chromium and webkit and uploads the `playwright-report` artifact.

## CI

- `.github/workflows/ci.yml`: on push and pull request, install, lint, typecheck, build, size, exports check, then the Playwright suite.
- `.github/workflows/publish.yml`: the same checks before publishing to npm.

## Working rules

Carried over from the maintainer's previous instruction file on 2026-09-23, with the maintainer's approval.

- Read and follow `ARCHITECTURE.md` before any change; its hard rules (§2) are never broken. Read `HANDOFF.md` for current status and next steps.
- Work one phase at a time (`ARCHITECTURE.md` §15). Stop at the end of each phase, report, and wait for approval.
- Ask the maintainer when something is not covered by `ARCHITECTURE.md`. Do not guess. Add new questions to §14.
- After each phase, update the checklist in `ARCHITECTURE.md` §15 and the status in `HANDOFF.md`.
- Run `bun run build` and `bun run size` before finishing a phase, and report gzip sizes against the baseline.
- Reply to the maintainer in Portuguese (Brazil), simple and clear: short bullets, brief explanations, questions as a numbered list.
- When a `senior-frontend-architect` skill is available, use it for architecture, review and CSS/JS library work.
